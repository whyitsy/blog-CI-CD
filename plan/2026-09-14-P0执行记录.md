## Task 3 · `.editorconfig` + 格式门禁 ✅

| 项 | 结果 |
|---|---|
| 新增 | `.editorconfig` |
| 改动 | `.github/workflows/ci.yml`（backend 作业新增"检查 C# 格式"步骤）+ 26 个 C# 文件的一次性格式化 |
| 门禁本地复现 | `dotnet format … whitespace --verify-no-changes --no-restore` → **通过** |
| YAML 校验 | 4 个作业；backend 15 步；格式检查位于"还原依赖"之后、"编译"之前 ✅ |

**两条实测得到的经验（都已写进 `.editorconfig` 注释）**：

1. **`end_of_line = lf` 是必须的。** 加之前，`dotnet format` 提议的替换内容全是 `'\r\n'`——
   它会与 `.gitattributes` 和 hygiene 作业**直接冲突**；加了之后 CRLF 提案归零。
2. **只在 whitespace 上设门禁。** `--severity info` 在本仓库报 21 条 analyzer 建议
   （CA2016/CA1873/CA1816/CA1861/SYSLIB1045/ASP0025），一次性纳入属过度工程化。

**对计划的一处偏离**：计划写的是把门禁放进 `hygiene` 作业，实际放进了 `backend` 作业。
理由：hygiene 刻意不装 .NET SDK（5 秒跑完，设计意图是"最快失败"），
装 SDK + restore 会让它失去这个性质。放在 backend 的 restore 之后、
build/test 之前，既复用了还原结果，又仍然**早于**昂贵的测试。

## Task 4 · 备份与恢复脚本 ✅

| 项 | 结果 |
|---|---|
| 新增 | `tools/backup/{backup.sh,restore.sh,README.md}`；`.gitignore` 增加 `backups/` |
| 真实备份 | `blog_blog_stage2_20260914-032545.sql.gz`，**9915 字节** |
| **真实还原演练** | `Posts=3`、`Users=2`、`zhparser 扩展=1`、`chinese 检索配置=1` ✅ |

**⭐ 演练当场推翻了一个错误假设（这是本次最有价值的一条记录）**

我最初在 README 里写的是「zhparser 扩展与 chinese 配置**不在** `pg_dump` 的输出里」。
演练后核实：**错**。dump 第 26 行就是 `CREATE EXTENSION IF NOT EXISTS zhparser WITH SCHEMA public;`，
第 40 行起是 `CREATE TEXT SEARCH CONFIGURATION public.chinese (…)`。

真实风险是另一回事，且已用实验证实：把同一份 dump 灌进一个**普通的 `postgres:18.6`** 实例：

```
ERROR:  extension "zhparser" is not available
HINT:  The extension must first be installed on the system where PostgreSQL is running.
```

**数据在，检索能力不在。** 结论：还原的目标实例必须**预先装好 zhparser 扩展文件**
（它不在官方镜像里、必须自行编译）—— 这才是生产必须用 `deploy/postgres-zhparser.Dockerfile` 的真正理由。

📌 这条记录本身就是"备份没验证过等于没有备份"的最佳注脚：
**一个听起来合理但错误的假设，只有真跑一遍才会露出来。**
