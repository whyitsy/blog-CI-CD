### 顺带修掉的既有 Bug
- **`PagedResult` 字段名不一致**：前端类型写 `totalCount`，后端下发的是 `total`，
  导致新列表页与管理页的「共 N 篇文章」全部渲染成 `undefined`。已对齐为 `total`。
- `PostListItemDto` 声明了后端 `PostCardDto` 并不存在的 `wordCount` 字段，已移除。
- `SiteService.UpdateConfigAsync` 对已存在的 Key 直接调用 `ApplyOptimisticVersion`，
  传入 version<1 时抛 `ArgumentOutOfRangeException` 被转成 5000；现按「不存在=新增 / 存在=乐观锁」分支，非法版本返回 4001。

### 环境备忘（本轮新增/修正）
- **WSL 直连 localhost 不通**：后端虽监听 5131，但 WSL 侧 `curl 127.0.0.1:5131` 一律 connection refused（WSL2 localhost 转发未生效）。
  验证接口必须用 Windows 的 curl：`/mnt/c/Windows/System32/curl.exe -s --noproxy '*' http://localhost:5131/...`。
  注意 `--noproxy` 与 `*` 要分开传，合并写 `--noproxy=*` 会被 shell 展开。
- **`ASPNETCORE_ENVIRONMENT=Development` 在 WSL 启动 Windows exe 时不生效**，会导致连接串为空、
  `The ConnectionString property has not been initialized`。改用命令行参数 `--environment Development`。
- **`dotnet` 不在 PATH**：用 `/mnt/c/Program Files/dotnet/dotnet.exe`。
- **前端 dev server 必须用 Windows node**：WSL 的 node 缺 `@rolldown/binding-linux-x64-gnu`，
  报 `Cannot find native binding`。改用：
  `"/mnt/c/Program Files/nodejs/node.exe" ./node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173`。
- **截图验证**：Chrome headless 在 Windows 侧运行，`--screenshot` 的路径要用 Windows 形式（如 `D:\tmpbuild\shots\x.png`）。
  截图前建议 `taskkill /F /IM chrome.exe` 清残留进程，否则可能挂住不退出。
- **改完后端要重启**：`dotnet build` 会因 `Blog.WebApi.exe` 占用 dll 而失败（MSB3027/MSB3021），
  先 `taskkill /F /IM Blog.WebApi.exe` 再构建。
