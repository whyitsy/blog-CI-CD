# tools/e2e · 浏览器级（CDP）自动化检查

> **这是什么**：用 Chrome DevTools Protocol 直接驱动真实浏览器，检查那些
> **后端集成测试测不到**的东西 —— 路由守卫、按角色裁剪 UI、表单提交链路、
> 页面在接口失败时的表现、以及少数可判定的视觉规则。
>
> **这一段曾经在仓库外面。** 原来有 29 个 `.mjs` 躺在 `D:\tmpbuild\`，
> 没有任何版本控制 —— 换台机器、重装系统、清一次临时目录就全没了。
> 这就是 [docs/06 §2](../../docs/06-技术债与待办.md) 里的 **G2**。
>
> **为什么零依赖**：Node 22+ 内置全局 `WebSocket`，CDP 就够用了。
> 所以这里**没有 `package.json`、没有 `npm install`**，也没有 puppeteer/playwright。
> 这不是偷懒 —— 浏览器驱动框架会带来安装体积、版本漂移和 CI 集成成本，
> 而本项目需要的能力（开页面、求值、断言、截图）CDP 原语直接覆盖。

---

## 一、先起三样东西

| 需要什么 | 怎么起 | 少了它会怎样 |
|---|---|---|
| **前端 dev server** | `Blog.FrontEnd` 下 `npm run dev`（见 [docs/05 §4.3](../../docs/05-运维与部署手册.md)） | preflight 直接拦住，不会跑 |
| **后端**（经 Vite 代理） | `Blog.Backend` 下 `dotnet run --project Blog.WebApi`（[docs/05 §4.1](../../docs/05-运维与部署手册.md)） | 只告警；需要真实数据的检查会失败 |
| **带调试端口的 Chrome** | `pwsh -File tools/e2e/start-chrome.ps1` | preflight 直接拦住，不会跑 |

> ⚠️ **Windows + WSL 的坑**：本项目的开发环境是「Windows 编译 + WSL 发命令」。
> Windows 的 Chrome 只监听 **Windows** 的 `127.0.0.1`，而 WSL2 的 `localhost` 是
> **WSL 自己的**回环 —— 两边不是同一个网络栈。所以在 WSL 里 `curl 127.0.0.1:9222`
> 会连不上，而 Windows 侧一切正常。
>
> **结论：这个环境下，Chrome 和 node 都要从 Windows 侧起/跑。**
>
> ```bash
> # 1) 起 Chrome（Windows 侧；用 WSL 的 pwsh 或 PowerShell 都行）
> pwsh.exe -File tools/e2e/start-chrome.ps1
>
> # 2) 跑检查（必须用 Windows 的 node，且传 Windows 路径）
> "/mnt/c/Program Files/nodejs/node.exe" 'D:\dotNET项目\Stage2\tools\e2e\run.mjs'
> ```
>
> 如果哪天开了 WSL 的 mirrored networking（`.wslconfig` 里 `networkingMode=mirrored`），
> WSL 就能直接连上，那时用 WSL 的 node 跑会更顺手。

## 二、怎么跑

```bash
node tools/e2e/run.mjs              # 全跑，最后给汇总表
node tools/e2e/run.mjs 03 07        # 只跑 03 和 07
node tools/e2e/run.mjs auth-flow    # 按名字片段筛选
```

退出码：**0 = 全绿，1 = 有失败，2 = 前置条件不满足**。
所以它可以直接当门禁用（`node run.mjs || exit 1`）。

截图落在 `tools/e2e/artifacts/<检查名>/`（已在 `.gitignore` 里，是运行产物）。
`E2E_SHOTS=0` 可以关掉截图。

## 三、检查清单

> **数量账**：仓库外原有 **29 个** `.mjs` → 其中**有断言**的 **11 个**被改写进来 →
> 最终 **10 个检查**。差的 1 个是合并来的：
> `collections-empty.mjs` 与 `backend-down-public-pages.mjs` 的前置条件互相冲突
> （一个要求后端在跑、一个要求后端停掉），不可能在同一次运行里都满足，
> 所以合并成 `07-public-lists-failure` 并用**伪造失败**代替"真的去停后端"。
> 另外 `guard-check.mjs` 与 `guard-check-win.mjs` 只差一次 `localStorage.clear()`，
> 只保留了后者。剩下 **18 个**是一次性的 `peek*` / `skel*` 探针脚本，**刻意没有搬**
> —— 把草稿纸放进仓库等于给仓库增加没人维护的文件（判断依据见第四节）。

|---|---|---|---|

| 02 | `auth-flow` | token 真的被用上了（`/api/users` 200）；作者打管理接口被**服务端**拒 403；清凭证后回登录页 | 种子账号 |
| 03 | `role-ui` | 「快速新建分类/标签」只给管理员看 | 种子账号 |

| 05 | `public-collections` | 专栏列表/详情/导航入口/文章页徽章，**界面与接口逐项一致** | ≥1 个专栏 |
| 06 | `collection-manage` | 编排面板上移 → 保存 → **顺序真的持久化到后端** | 有 ≥2 篇文章的专栏 |

## 四、⚠️ 搬进仓库时改掉的三类问题

直接 `cp` 过来是不行的。原脚本里有三类东西会让它在**你的**机器以外跑不起来，
或者更糟 —— **在你自己的机器上第二次运行就红**。

### 1. 硬编码的机器相关值 → 全部走环境变量

| 原来写死 | 现在 |
|---|---|
| `http://localhost:5173` | `E2E_BASE_URL` |
| `http://127.0.0.1:9222` | `E2E_CDP_URL` |
| `D:/tmpbuild/shots/` | `E2E_ARTIFACTS_DIR`（默认 `tools/e2e/artifacts/`） |
| `admin@example.com` / `Admin@12345` | `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD` |
| `'blog-auth-token'` 等 localStorage 键名 | `lib/config.mjs` 的 `storageKeys`（单一来源） |

> 写死的后果不是"不好看"，而是**搬进仓库等于没搬**：
> 换台机器、换个端口、换套种子数据就全红，然后你会得出"这些脚本没用"的结论。

### 2. 写死的测试数据 → 先问接口要，再断言界面与接口一致

最典型的是 `05`。原来它断言这些**具体字符串**：

```
'csharp-advanced'   'C# 进阶系列'   '更新标题-标签同步验证'
'01a07531-b772-7624-8624-123c23236859'   '2 篇文章'
```

那些是**当时那台机器的开发库**里的数据。你在后台改个标题，它就红 —— 而代码一行没错。

现在改成：**先 `GET /api/collections` 拿数据，再断言界面和接口说的完全一样**。
这样不但不依赖具体数据，断言强度还更高（原来只验"出现了某几个字"，
现在验"界面与接口逐项一致"）。

### 3. ⭐ 不可重复运行 → 每次运行用唯一后缀

这是最容易被忽略、后果最坏的一类。原脚本创建的是**写死名字**的实体：

```js
setVal(email, 'uitest@example.com')     // 第一次成功
                                        // 第二次 → 邮箱已被占用 → 检查失败
```

于是**同一个脚本第二次运行必然失败**，而失败原因和代码质量毫无关系。

> 一套"只能跑一次"的检查比没有检查更糟 ——
> **它会训练你忽略红色**（[docs/06 §2](../../docs/06-技术债与待办.md) 讲过这个机制）。

现在创建实体用 `runId()` 生成唯一后缀（`e2e-user-0914-0202-34@example.com`），
并且**跑完尽力清理**创建的实体（清理失败只提示、不算失败 —— 它不是被测对象）。

**仍需知道的副作用**：

| 检查 | 副作用 | 为什么不能完全清掉 |
|---|---|---|
| 09 | 开发库里会积累**已停用**的测试账号 | `/api/users` **没有删除接口**，只有 `disable`（见 `UsersController`）。⚠️ 所以脚本跑完会**尽力把本次创建的账号停用** —— 一个「还活着、密码写在脚本里」的账号比一行死数据危险得多 |
| 04 / 10 | 会创建一篇文章 / 一位作者 | 有删除接口，已尽力清理；失败时会在输出里提示 |
| 06 | 会改变专栏内的文章顺序 | 断言完**会把顺序恢复原样**；恢复失败会提示 |

## 五、⚠️ 这套检查**不能**替代的东西

| 🚫 它测不了 | 为什么 | 那靠什么 |
|---|---|---|
| 「好不好看」 | 「显眼」「协调」没有可判定的定义 | **人眼**（[archive/问题排查记录.md §2](../../archive/问题排查记录.md) 的待跟进项） |
| 动画、过渡、响应式断点 | 断言动画基本等于断言实现细节 | 人眼 + 偶尔录屏 |
| 无障碍（键盘可达、读屏） | CDP 能做但需要专门写，成本不低 | 目前没做，属于已知缺口 |
| 后端业务规则 | 那是集成/单元测试的活 | `dotnet test`（[docs/05 §4.2](../../docs/05-运维与部署手册.md)） |

> 这张表和 [learn/02 §5.1](../../learn/02-CI-CD实践.md) 的「测试金字塔」是同一件事：
> **每一层只负责它擅长的那部分**。指望 E2E 覆盖业务规则，会得到一套又慢又脆的检查。

## 六、为什么这些检查**没有**接进 CI

`learn/02` §5.5 第 11 条的状态是「❌ 未做（G2）」，而 G2 只要求**先把脚本移进仓库**。
接进 CI 是**另一件事**，理由是：

| 成本 | 具体表现 |
|---|---|
| 需要真浏览器 | CI 里要装 Chrome，或者维护一个带 Chrome 的镜像 |
| 随机失败的来源成倍增加 | 渲染时机、字体、动画 —— 每一个都能让红色变得不可信 |
| 收益需要真实数据支撑 | 05/06/08 都依赖开发库里的种子数据，CI 上得先造一套 |

**做这件事的正确顺序**：先让它在本地稳定跑（现在这一步），
等它连续一段时间**没有出现过假红**，再考虑接 CI。反过来做的话，
你会得到一个"偶尔红、重跑就好"的流水线 —— 那比没有更糟。

## 七、遇到问题先看这里

| 现象 | 最可能的原因 |
|---|---|
| `连不上 Chrome 的调试端口` | Chrome 没起；或者已有 Chrome 占用了默认配置目录（用 `start-chrome.ps1` 的独立 `user-data-dir` 可避开） |
| WSL 里连不上 `127.0.0.1:9222` | 网络栈不同，见第一节的警告。用 Windows 的 node 跑 |
| `期望 /admin/login 实际 /admin` | 前端 dev server 没连上后端 / 或本地残留了登录态（断言前会 `localStorage.clear()`，若仍如此则是守卫有问题） |
| `SKIP 开发库里一个专栏都没有` | 前置数据不足。**跳过不等于通过** —— 那部分没有被验证 |
| 断言 `定位并填写标题与正文` 失败 | 表单 placeholder 改过了。选择器在 `04-author-flow.mjs` 里，改选择器而不是改断言 |
| 全部检查都在同一步失败 | 多半是前端没起或后端挂了，先看 `run.mjs` 的 preflight 输出 |
| `05` 说「接口返回 N 个专栏」比实际少，或跳过详情验证 | **专栏列表缓存陈旧**（`GET /api/collections` 走缓存，TTL 约 30 分钟；详情接口不走） | `docker exec -i redis redis-cli DEL blog:taxonomy:collections:v1:published`。⚠️ 若你是**用 SQL 直接改的库**，那一定会遇到这个 —— 直接改库绕过了应用的缓存失效 |
| 某一步报 `Unexpected end of JSON input` | 后端/代理返回了非 JSON（多半是没在跑） | 现在会直接说明「服务端返回的不是 JSON（HTTP 502）—— 后端或反向代理很可能没有在运行」，照着提示起后端即可 |
