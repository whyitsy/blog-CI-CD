## 3. 路由设计

`src/router/index.ts`。`/`、`/login`、`/me`、`/admin` 四个顶层入口对应三套布局 + 一个独立登录页：

```
/                       DefaultLayout（公开站点）
├─ ''                   home              首页
├─ post/:id             post-detail       文章详情
├─ tags / categories    tags / categories 标签墙 / 分类墙
├─ archive              archive           归档时间轴
├─ posts                post-list         通用列表（tag/category/author 筛选）
├─ collections          collections       专栏列表
└─ collections/:slug    collection-detail 专栏详情
/login                  LoginView（独立极简布局，不套任何 Layout）；/admin/login → 重定向到 /login
/:pathMatch(.*)*        not-found         404 页

/me     AuthorLayout（requiresAuth + roles:[Author, Admin]）：
        '' my-posts ｜ posts/new my-post-new ｜ posts/:id/edit my-post-edit ｜ profile my-profile
/admin  AdminLayout（requiresAuth + roles:[Admin]）：
        '' admin-posts ｜ posts/new ｜ posts/:id/edit ｜ categories ｜ tags ｜ users ｜ authors ｜
        collections ｜ profile（→ admin-authors） ｜ site
```

### 3.1 为什么拆成三套布局

**起因是布局遮挡**：若 `/admin` 直接挂在公开的 `DefaultLayout` 下，`NavBar` 是 `position: fixed`（高 64px）
而页面没有对应的顶部留白，"文章管理"的标题就会被导航栏压住。
解法不是加 padding 打补丁，而是**从结构上消除遮挡**：

| 布局 | 适用路由 | 内容 |
|---|---|---|
| `DefaultLayout` | 公开站点 | `NavBar`（fixed） + `<RouterView>` + `SiteFooter` + 搜索弹窗 |
| `AuthorLayout` | `/me/**` | 作者工作区导航 |
| `AdminLayout` | `/admin/**` | 左侧固定侧边栏 + 顶栏模块名 + 内容区；≤880px 折叠为**单行横向滚动 tab** |

`App.vue` 因此只保留一个顶层 `<RouterView>`，不再全局套布局。
`AdminLayout` 的高亮与标题用**最长前缀匹配**决定，避免 `/admin/profile` 被 `/admin` 抢先命中。

### 3.2 路由 meta 与守卫

`RouteMeta` 扩展了三个字段（用 `declare module 'vue-router'` 声明）：

| meta | 含义 |
|---|---|
| `requiresAuth` | 需要登录 |
| `roles` | 允许的角色数组；不填则任何已登录用户可访问 |
| `guestOnly` | 仅未登录可访问（登录页） |

```
guestOnly 且已登录  → 送回各自首页（Admin → /admin，Author → /me）
不需要认证         → 放行
未登录             → 跳 /login?returnUrl=<原路径>
角色不符           → 送回自己的地盘（同上），不报错页
```

> ⚠️ **路由守卫只是前端体验控制，可被绕过（改 JS 即可）。**
> **真正的安全边界在后端**——所有受保护操作后端都会再校验角色与资源归属。

## 4. API 访问层

### 4.1 设计原则与注入模式

| 原则 | 实现 |
|---|---|
| 统一解包响应体 | `request()` 返回 `body.data`，`code !== 0` 时抛 `ApiError` |
| 不产生循环引用 | `http.ts` **不导入 store / router**，由 `main.ts` 通过 `configureHttp()` 注入 |
| 类型对齐后端 | 所有 DTO 类型集中在 `types/index.ts` |
| 错误可分支 | `ApiError` 携带后端业务码，另有 `isNotFoundError()` 辅助函数 |

若 `http.ts` 直接 `import { useAuthStore }`，就会形成 `http → store → api → http` 的循环引用。
因此接线集中在 `main.ts`：

```ts
configureHttp({
  getToken: () => auth.token,
  onUnauthorized: () => {          // 已经在登录页时不要跳转，否则会把「密码错误」提示冲掉
    const onLoginPage = router.currentRoute.value.meta.guestOnly === true
    auth.clear()
    if (!onLoginPage) void router.replace({ name: 'login', query: { returnUrl: router.currentRoute.value.fullPath } })
  },
})
```

### 4.2 请求处理细节

| 细节 | 处理 |
|---|---|
| 认证头 | 有 token 时自动加 `Authorization: Bearer <token>` |
| `Content-Type` | JSON 请求设 `application/json`；**FormData 不设**（让浏览器自己生成 multipart boundary） |
| 网络异常 | 抛 `ApiError(-1, '网络异常，请检查后端服务是否启动')` |
| 非 JSON 响应 | 按 HTTP 状态兜底：429 → 限流文案；401 → 触发 `onUnauthorized`；404 → "请求的资源不存在"；其他 → "服务暂时不可用" |
| 业务错误 | `code === 4010` 时触发 `onUnauthorized` |
| 文案中性化 | 兜底错误**不把 HTTP 状态码暴露给用户**；状态码仍保留在 `ApiError.code` 里供排查 |

### 4.3 公开页加载失败：一律回落空状态（重要）

**公开页面（访客可见的只读列表页）加载失败时不显示错误横幅**，而是让模板的
`v-else-if="list.length === 0"` 分支自然命中：`catch` 里把数据置空 + `console.error`，
**不设置任何错误文案变量**。

```ts
try {
  collections.value = await getCollections()
} catch (e) {
  collections.value = []                             // ← 回落为空列表
  console.error('[collections] 加载专栏列表失败：', e)  // ← 技术细节只进控制台
}
```

覆盖面：`/`、`/posts`、`/archive`、`/post/:id` 显示空状态/骨架屏消失，
`/tags`、`/categories`、`/collections` 显示"暂无标签 / 分类 / 专栏"。

为什么这样定：

1. **公开页不该暴露基础设施故障**。"服务暂时不可用"对访客没有可操作性，空状态则中性、稳定。
2. **不要"让错误分支吃掉空状态"**：写成 `v-else-if="!errorMsg && list.length === 0"` 时，
   后端一旦未启动 `errorMsg` 就有值，**「暂无专栏」会被永久抑制**，页面只剩一句错误提示。

> ⚠️ **管理端页面（`/admin/**`、`/me/**`）相反**：它们**应该**显示错误横幅——
> 操作者需要知道"保存失败/加载失败"以及原因。
> **判断依据不是"能不能拿到错误"，而是"读者此时需要什么信息"。**

### 4.4 错误码常量与 API 模块

`http.ts` 里镜像了一份后端错误码（`ErrorCode`），与 `ErrorCodes.cs` 一一对应：
`Ok 0` / `InvalidArgument 4001` / `BusinessRule 4002` / `DuplicateResource 4003` /
`Unauthorized 4010` / `Forbidden 4030` / `NotFound 4040` / `ConcurrencyConflict 4090` /
`RateLimited 4091` / `PayloadTooLarge 4130` / `InternalError 5000`。

> ⚠️ 这是**手动同步**的常量表。改动后端错误码时必须同时改 `http.ts` 与 `types`。

| 文件 | 关键函数 |
|---|---|
| `api/http.ts` | `get` / `post` / `put` / `del` / `upload` / `configureHttp` / `ApiError` / `ErrorCode` |
| `api/posts.ts` | `getPosts` / `getPostDetail` / **`getPostDetailReadonly`** / `searchPosts` / `getArchives` / 增删改与发布 |
| `api/{auth,authors,categories,tags,collections,site,users}.ts` | 与同名控制器对应：列表 / 详情 / 增删改（collections 另有编排；site 另有 `getSiteStats`） |
| `api/files.ts` | `upload()` |

> **`getPostDetail` vs `getPostDetailReadonly`**：前者会让浏览量 +1（读者看的页面），
> 后者不会（管理端/编辑器取数据用，同时拿到 `version`）。用错会导致"后台点一次编辑就 +1"的统计失真。

## 5. 状态管理

只有三个 store，**刻意保持精简**。

| store | 内容 |
|---|---|
| `stores/auth.ts` | state：`token` / `user` / `expiresAt` / `verified`；getters：`isAuthenticated` / `role` / `isAdmin` / `canWriteContent` / `displayName`；actions：`setSession` / `clear` / `restore`。持久化在 `localStorage`（`blog-auth-token` / `blog-auth-user` / `blog-auth-expires`） |
| `stores/app.ts` | `useThemeStore`（`theme` 默认 `dark`；`apply()` 写 `<html data-theme>`；持久化键 `blog-theme`）与 `useSearchStore`（`open` / `show()` / `hide()`，供 `Ctrl/Cmd + K` 与 `SearchModal` 用） |
| `stores/site.ts` | 站点配置、社交链接与统计（首屏与 Footer 共用）。**管理端保存后调用 `refreshAll()` 刷新全站**，避免各处缓存不一致 |

> **localStorage 存 token 的权衡**：优点是不会自动随请求发送，因此**不引入 CSRF 问题**；
> 缺点是 JS 可读，一旦 XSS 即被窃取——用"短有效期（30 分钟）"补偿。
> 不用 cookie 是因为本项目用 Bearer token，且后端 CORS 未启用 `AllowCredentials`。

`restore()` 在应用启动时调用：本地有 token 就向后端确认一次（`GET /api/auth/me`），失败即清理。
这样能正确处理**"token 未过期但账号已被停用/改密"**的情况（后端 `TokenVersion` 校验会拒绝，`/me` 返回 401）；
本地已知过期时直接清理，省一次请求。

### 6.3 媒体字段：只能上传，不能填 URL

四个「图片地址」字段（作者头像、文章封面、站点 Logo、首屏背景图）的前端形态
**统一为「上传按钮 + 预览 + 移除」**，**不提供任何文本框**。涉及
`views/AdminAuthorListView.vue`、`views/me/MyProfileView.vue`、
`components/admin/PostEditor.vue`、`views/AdminSiteConfigView.vue` 四处。

> ⚠️ **这只是 UI 约束，不是安全边界。** 真正的拦截在服务端 `MediaPath` 白名单
> （[02-架构与数据模型.md](./02-架构与数据模型.md)）。前端做这件事的目的是**让正常用户没有机会填错**——
> 攻击者本来就不会打开你的页面，他会直接 `curl`。

### 6.4 Markdown 渲染与首屏背景图

`utils/markdown.ts` 的 `renderMarkdown(content)` 封装 `marked` + `DOMPurify`，
是正文进 `v-html` 的**唯一**入口：`ADD_ATTR: ['id']`（标题锚点）、`FORBID_ATTR: ['style']`（见下），
外加 `uponSanitizeElement` 钩子把 `<font>` 标签 **unwrap**（保留子节点、丢掉标签本身），
而不是整块删掉——否则正文文字会一起消失。

**为什么要剥内联 `style`**：正文常常是从富文本编辑器**粘贴**进来的，会夹带
`<font style="color:rgb(15, 17, 21);">`（近黑色）。**内联样式优先级高于 `var(--text-*)` 主题变量**，
于是亮色主题下看不出问题、暗色主题下变成黑底黑字。根因不是主题没适配，而是有更高优先级的东西把主题盖住了。

> ⚠️ **不要把 `sanitize` 写在视图组件里**：`DOMPurify.addHook` 是**全局**的，
> 组件被反复挂载（或 Vite HMR）会重复注册。抽成模块 + 模块级去重标志才能保证只注册一次。

首屏背景图由 `HeroSection.vue` 从 `site.config.heroBackgrounds` 里**随机挑一张**：

```ts
watch(backgrounds, (list) => {
  if (!list.length) { pickedBackground.value = ''; return }
  if (!list.includes(pickedBackground.value)) pickedBackground.value = list[Math.floor(Math.random() * list.length)]
}, { immediate: true })
```

| 写法 | 为什么不行 |
|---|---|
| 在 `onMounted` 里挑 | 站点配置是**异步**拉的，挂载时 `config` 往往还是 `null`，会永远挑不到图。必须用 `watch(..., { immediate: true })` |
| 每次列表变化都重新抽 | `site.refreshAll()` 之类的刷新会把访客**正在看**的背景换掉。只在「当前这张已不在列表里」时才重抽 |

列表为空时 `pickedBackground` 为空串，模板**不渲染**图片层与遮罩，只留 `.aurora-blobs` 的渐变。

## 7. 样式体系

### 7.1 三层结构与主题

| 层 | 文件 | 内容 |
|---|---|---|
| **令牌层** | `styles/tokens.css` | CSS 自定义属性：颜色、字体、间距、圆角、阴影、动效 |
| **基元层** | `styles/global.css` | reset、排版、通用工具类（`.container` / `.card` / `.glass` / `.gradient-text` / 徽章类 / 骨架基元 / 过渡） |
| **组件层** | 各 `.vue` 的 `<style scoped>` | 组件私有样式 |

**暗色是默认**，通过 `<html data-theme="light">` 切换，同时支持 `prefers-color-scheme: light`。
令牌以 `--bg-*` / `--text-*` / `--brand-*` / `--border-*` / `--status-*` 命名，具体色值见 `tokens.css`。

### 7.2 `.aurora-blobs`：全局的「内置渐变背景」

`.aurora-blobs` 是**全局**基元，被 **7 处**复用：首屏 `HeroSection`、归档、专栏列表、专栏详情、
文章列表、404、登录表单（`LoginForm`）。首屏背景图留空时，它就是配置页里所说的「内置渐变背景」的本体。
设计要点：

| 要点 | 原因 |
|---|---|
| 两个光斑**水平居中**（`left:50%` + 负 `margin-left`） | 只亮对角会让中间空一片，观感不像"渐变背景" |
| 尺寸 760 / 820px，不透明度较高；另有一层 `radial-gradient` 打底 | 太小太淡、光斑之外死黑，都会接近纯色底 |
| 亮色主题单独一套更低的不透明度 | 亮底下同样的透明度会糊成一片 |

> 居中用的是 `left:50%` + 负 `margin-left`，**不是** `transform: translateX(-50%)` ——
> 留出 `transform` 给将来的动画用，避免互相覆盖。

### 7.3 徽章与响应式

分类徽章与标签徽章是**全局类**（`.category-badge` 实心渐变方块 / `.tag-badge` 细边框圆角青色），
不是组件；专栏徽章是虚线 + 📚，三者视觉可区分。

> ⚠️ **scoped 选择器带 `data-v` 属性，优先级高于全局类。** 如果组件内也写了 `background`，
> 会盖掉全局样式。`PostCard.vue` 的 `.cover-category` 踩过这个坑，现在只保留定位属性。

| 断点 | 布局 |
|---|---|
| ≥1200px / 768–1199px / <768px | 三列 / 两列 / 单列卡片 |
| ≤880px | `AdminLayout` 侧边栏折叠为横向 tab |

## 8. 认证闭环（前端侧）

| 环节 | 实现 |
|---|---|
| 登录页 / 注册页 | `/login`，管理员与作者**共用**（`LoginForm` 的 `mode` 只影响文案）；**没有注册页**（决策 T1：作者账号由管理员创建） |
| token 存储 / 请求带 token | `localStorage`（见 §5）；`http.ts` 经注入的 `getToken` 取值 |
| 401 处理 | `onUnauthorized` 清登录态并跳登录页（**已在登录页时不跳**，以免冲掉错误提示） |
| 启动恢复 | `main.ts` 在挂载前调用 `auth.restore()` |
| 路由守卫 / 角色落地 | 见 §3.2；Admin → `/admin`，Author → `/me`；角色不符送回自己的地盘，不报错页 |
| 编辑器隐藏入口 | `PostEditor` 用 `canManageTaxonomy` 对作者隐藏"快速新建分类/标签" |

> ⚠️ **归属校验只认 `CreatedByUserId`（账号维度），不能认 `AuthorId`**：
> 多个账号可关联同一 Author，用 `AuthorId` 判断会导致互相越权。
> 详情页返回的 `createdByUserId` 就是为此提供的。
