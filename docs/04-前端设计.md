### 1.3 Vite 配置

`vite.config.ts` 的三个要点：

| 配置 | 值 | 说明 |
|---|---|---|
| 别名 | `@` → `./src` | 全项目统一用 `@/` 导入 |
| dev 端口 | `5173` | |
| 代理 | `/api` → `VITE_PROXY_TARGET`（默认 `http://localhost:5131`） | **代理目标来自环境变量，不硬编码** |

## 3. 路由设计

`src/router/index.ts`

### 3.1 三个父路由 = 三套布局

```
/                       DefaultLayout（公开站点）
├─ ''                   home            首页
├─ post/:id             post-detail     文章详情
├─ tags                 tags            标签墙
├─ categories           categories      分类墙
├─ archive              archive         归档时间轴
├─ posts                post-list       通用列表（tag/category/author 筛选）
├─ collections          collections     专栏列表
└─ collections/:slug    collection-detail 专栏详情

/login                  LoginView（独立极简布局，不套任何 Layout）
/admin/login            → 重定向到 /login（保留旧链接）

/me                     AuthorLayout（作者工作区，requiresAuth + roles:[Author,Admin]）
├─ ''                   my-posts        我的文章
├─ posts/new            my-post-new     新建
├─ posts/:id/edit       my-post-edit    编辑
└─ profile              my-profile      我的署名资料

/admin                  AdminLayout（管理后台，requiresAuth + roles:[Admin]）
├─ ''                   admin-posts     文章管理
├─ posts/new            admin-post-new
├─ posts/:id/edit       admin-post-edit
├─ categories           admin-categories
├─ tags                 admin-tags
├─ users                admin-users     账号管理
├─ authors              admin-authors   作者管理
├─ collections          admin-collections 专栏管理
├─ profile              → 重定向到 admin-authors
└─ site                 admin-site      网站配置

/:pathMatch(.*)*        not-found       404 页
```

### 3.2 为什么拆成三套布局

**起因是一个真实的布局 Bug**：`/admin` 最初直接挂在公开的 `DefaultLayout` 下，
而 `NavBar` 是 `position: fixed`（高 64px），页面却没有对应的顶部留白，
于是"文章管理"的标题被导航栏压住。

修复方式不是加 padding 打补丁，而是**从结构上消除遮挡**：

| 布局 | 适用路由 | 内容 |
|---|---|---|
| `DefaultLayout` | 公开站点 | `NavBar`（fixed） + `<RouterView>` + `SiteFooter` + 搜索弹窗 |
| `AuthorLayout` | `/me/**` | 作者工作区导航 |
| `AdminLayout` | `/admin/**` | 左侧固定侧边栏 + 顶栏模块名 + 内容区 |

`App.vue` 因此只保留一个顶层 `<RouterView>`，不再全局套布局。

> **`AdminLayout` 的响应式细节**：≤880px 时侧边栏折叠为**单行可横向滚动的 tab**。
> 高亮与标题用**最长前缀匹配**决定，避免 `/admin/profile` 被 `/admin` 抢先命中。

### 3.3 路由 meta 与守卫

`RouteMeta` 扩展了三个字段（用 `declare module 'vue-router'` 声明）：

| meta | 含义 |
|---|---|
| `requiresAuth` | 需要登录 |
| `roles` | 允许的角色数组；不填则任何已登录用户可访问 |
| `guestOnly` | 仅未登录可访问（登录页） |

守卫逻辑：

```
guestOnly 且已登录        → 送回各自首页（Admin → /admin，Author → /me）
不需要认证               → 放行
未登录                   → 跳 /login?returnUrl=<原路径>
角色不符                 → 送回自己的地盘（Admin → /admin，Author → /me），不报错页
```

> ⚠️ **路由守卫只是前端体验控制，可被绕过（改 JS 即可）。**
> **真正的安全边界在后端**——所有受保护操作后端都会再校验角色与资源归属。

## 4. API 访问层

### 4.1 设计原则

| 原则 | 实现 |
|---|---|
| 统一解包响应体 | `request()` 返回 `body.data`，`code !== 0` 时抛 `ApiError` |
| 不产生循环引用 | `http.ts` **不导入 store / router**，由 `main.ts` 通过 `configureHttp()` 注入 |
| 类型对齐后端 | 所有 DTO 类型集中在 `types/index.ts` |
| 错误可分支 | `ApiError` 携带后端业务码，另有 `isNotFoundError()` 辅助函数 |

### 4.2 `configureHttp` 注入模式

这是本项目避免循环依赖的关键技巧：

```ts
// main.ts —— 在这里接线
configureHttp({
  getToken: () => auth.token,
  onUnauthorized: () => {
    // 已经在登录页时不要跳转，否则会把「密码错误」提示冲掉
    const onLoginPage = router.currentRoute.value.meta.guestOnly === true
    auth.clear()
    if (!onLoginPage) {
      const returnUrl = router.currentRoute.value.fullPath
      void router.replace({ name: 'login', query: returnUrl !== '/' ? { returnUrl } : {} })
    }
  },
})
```

若 `http.ts` 直接 `import { useAuthStore }`，就会形成
`http → store → api → http` 的循环引用。

### 4.3 请求处理细节

| 细节 | 处理 |
|---|---|
| 认证头 | 有 token 时自动加 `Authorization: Bearer <token>` |
| `Content-Type` | JSON 请求设 `application/json`；**FormData 不设**（让浏览器自己生成 multipart boundary） |
| 网络异常 | 抛 `ApiError(-1, '网络异常，请检查后端服务是否启动')` |
| 非 JSON 响应 | 按 HTTP 状态兜底：429 → 限流文案；401 → 触发 `onUnauthorized`；404 → "请求的资源不存在"；其他 → "服务暂时不可用" |
| 业务错误 | `code === 4010` 时触发 `onUnauthorized` |
| 文案中性化 | 兜底错误**不把 HTTP 状态码暴露给用户**；状态码仍保留在 `ApiError.code` 里供排查 |

### 4.4 公开页加载失败的处理约定（重要）

**公开页面（访客可见的只读列表页）在加载失败时，一律回落到「空状态」，不显示错误横幅。**

| 页面 | 加载失败时显示 |
|---|---|
| `/`、`/posts`、`/archive`、`/post/:id` | 空状态 / 骨架屏消失 |
| `/tags` | 暂无标签 |
| `/categories` | 暂无分类 |
| `/collections` | 暂无专栏 |

**做法**：在 `catch` 里把数据置空并 `console.error` 记录，**不设置任何错误文案变量**，
让模板的 `v-else-if="list.length === 0"` 分支自然命中。

```ts
try {
  collections.value = await getCollections()
} catch (e) {
  collections.value = []                       // ← 回落为空列表
  console.error('[collections] 加载专栏列表失败：', e)   // ← 技术细节只进控制台
}
```

**为什么这样定**：

1. **公开页不该暴露基础设施故障**。`服务暂时不可用，请稍后重试` 对访客没有可操作性，
   而"空状态"视觉上是中性、稳定的。
2. **避免"错误分支吃掉空状态"**。曾经的写法是
   `v-else-if="!errorMsg && list.length === 0"` —— 一旦后端未启动，
   `errorMsg` 有值，**「暂无专栏」就被永久抑制**，页面只剩一句错误提示。
   这正是本项目修过的一个真实 Bug。
3. **一致性**。五个公开列表页里有四个是"吞错误、显空态"，
   只有一个例外就会让用户感觉"这个页面坏了"。

> ⚠️ **管理端页面（`/admin/**`、`/me/**`）相反**：它们**应该**显示错误横幅。
> 那里的用户是登录后的操作者，需要知道"保存失败/加载失败"以及原因。
> 因此 `/admin/**` 里的 `errorMsg` 是可接受的、也是必要的。
>
> **判断依据不是"能不能拿到错误"，而是"读者此时需要什么信息"**：
> 访客需要稳定的页面，操作者需要明确的失败反馈。

### 4.5 后端错误码常量

`http.ts` 里镜像了一份后端错误码（`ErrorCode`），与 `ErrorCodes.cs` 一一对应：
`Ok 0` / `InvalidArgument 4001` / `BusinessRule 4002` / `DuplicateResource 4003` /
`Unauthorized 4010` / `Forbidden 4030` / `NotFound 4040` / `ConcurrencyConflict 4090` /
`RateLimited 4091` / `PayloadTooLarge 4130` / `InternalError 5000`。

> ⚠️ 这是**手动同步**的常量表。改动后端错误码时必须同时改 `http.ts` 与 `types`。

| `api/auth.ts` | Auth | 登录 / `getMe` / 注销 |
| `api/posts.ts` | Posts | `getPosts` / `getPostDetail` / **`getPostDetailReadonly`** / `searchPosts` / `getArchives` / `createPost` / `updatePost` / `publishPost` / `deletePost` |
| `api/authors.ts` | Authors | 列表 / 单个 / `me` / 增删改 |
| `api/categories.ts` | Categories | 列表 / 增删改 |
| `api/tags.ts` | Tags | 列表 / 增删改 |
| `api/collections.ts` | Collections | 列表 / 详情 / 增删改 / 编排 |

## 5. 状态管理

只有三个 store，**刻意保持精简**。

### 5.1 `stores/auth.ts`

| 项 | 内容 |
|---|---|
| state | `token` / `user` / `expiresAt` / `verified` |
| getters | `isAuthenticated` / `role` / `isAdmin` / `canWriteContent` / `displayName` |
| actions | `setSession` / `clear` / `restore` |

持久化：`localStorage`，键为 `blog-auth-token` / `blog-auth-user` / `blog-auth-expires`。

> **localStorage 存 token 的权衡**：
> - 优点：不会自动随请求发送，因此**不引入 CSRF 问题**
> - 缺点：JS 可读，一旦 XSS 即被窃取 → 用"短有效期（30 分钟）"补偿
>
> 不使用 cookie，是因为本项目用 Bearer token，且后端 CORS 未启用 `AllowCredentials`。

`restore()` 在应用启动时调用：本地有 token 就向后端确认一次（`GET /api/auth/me`），
失败即清理。这样能正确处理**"token 未过期但账号已被停用/改密"**的情况
（后端 `TokenVersion` 校验会拒绝，`/me` 返回 401）。
本地已知过期时直接清理，省一次请求。

### 5.2 `stores/app.ts`

两个独立的小 store：

| store | 内容 |
|---|---|
| `useThemeStore` | `theme`（`dark` 默认）/ `apply()` 写 `<html data-theme>` / `toggle()`；持久化键 `blog-theme` |
| `useSearchStore` | `open` / `show()` / `hide()`；供 `Ctrl/Cmd + K` 与 `SearchModal` 使用 |

### 5.3 `stores/site.ts`

缓存站点配置、社交链接与统计（首屏与 Footer 共用）。
**管理端保存配置后调用 `refreshAll()` 刷新全站**，避免各处缓存不一致。

| `FormSkeleton` | 配置表单类页面 |

**全局基元**在 `styles/global.css`：`.shimmer` / `.sk-line` / `.sk-block` / `.sk-stack` / `.w-*`。
这些原本在 4 个视图里各写了一份完全相同的 CSS，组件化后收敛到一处。

> ⚠️ **骨架屏是瞬时状态，直接截图抓不到**（数据一回来就消失）。
> 正确的验证方法见 [07-开发与运维手册.md](./07-开发与运维手册.md) §6。

### 6.5 指令

`directives/typewriter.ts` — 打字机效果，在 `main.ts` 注册为 `v-typewriter`。
所有动画都适配 `prefers-reduced-motion: reduce`。

## 7. 样式体系

### 7.1 三层结构

| 层 | 文件 | 内容 |
|---|---|---|
| **令牌层** | `styles/tokens.css` | CSS 自定义属性：颜色、字体、间距、圆角、阴影、动效 |
| **基元层** | `styles/global.css` | reset、排版、通用工具类（`.container` / `.card` / `.glass` / `.gradient-text` / `.tag-badge` / `.category-badge` / 骨架基元 / 过渡） |
| **组件层** | 各 `.vue` 的 `<style scoped>` | 组件私有样式 |

### 7.2 主题机制

- **暗色是默认**，通过 `<html data-theme="light">` 切换
- 同时支持 `prefers-color-scheme: light` 媒体查询
- 令牌以 `--bg-*` / `--text-*` / `--brand-*` / `--border-*` / `--status-*` 命名

核心色（暗色主题）：

| 令牌 | 值 |
|---|---|
| `--bg-canvas` | `#13141A` |
| `--bg-surface` | `#1B1D24` |
| `--bg-raised` | `#23262F` |
| `--text-strong` | `#F2F5F9` |
| `--text-default` | `#CBDAE5` |
| `--text-muted` | `#A3A9B8` |
| `--brand-500` | `#22C5DC` |
| `--sub-500` | `#F4569D` |
| `--gradient-start/mid/end` | `#24C6DC` / `#5433FF` / `#FF0099` |

### 7.3 徽章为什么不组件化

分类徽章与标签徽章是**全局类**（`.category-badge` / `.tag-badge`），不是组件：

| 徽章 | 视觉 |
|---|---|
| `.category-badge` | 实心渐变方块 |
| `.tag-badge` | 细边框圆角（青色） |
| 专栏徽章 | 虚线 + 📚（三者可区分） |

> ⚠️ **scoped 选择器带 `data-v` 属性，优先级高于全局类。**
> 如果组件内也写了 `background`，会盖掉全局样式。
> `PostCard.vue` 的 `.cover-category` 踩过这个坑，现在只保留定位属性。

### 7.4 响应式断点

| 断点 | 布局 |

| ≥1200px | 三列卡片 |
| 768–1199px | 两列卡片 |
| <768px | 单列卡片 |
| ≤880px | `AdminLayout` 侧边栏折叠为横向 tab |

## 8. 认证闭环（前端侧）

| 环节 | 实现 |
|---|---|
| 登录页 | `/login`，管理员与作者**共用**（`LoginForm` 的 `mode` 只影响文案） |
| 注册页 | **没有**（决策 T1：作者账号由管理员创建） |
| token 存储 | `localStorage`（见 §5.1） |
| 请求带 token | `http.ts` 经注入的 `getToken` 取值 |
| 401 处理 | `onUnauthorized` 清登录态并跳登录页（**已在登录页时不跳**，以免冲掉错误提示） |
| 启动恢复 | `main.ts` 在挂载前调用 `auth.restore()` |
| 路由守卫 | 见 §3.3 |
| 角色落地 | Admin → `/admin`，Author → `/me` |
| 越权用户 | 角色不符时送回自己的地盘，不报错页 |
| 编辑器隐藏入口 | `PostEditor` 用 `canManageTaxonomy` 对作者隐藏"快速新建分类/标签" |

> ⚠️ **归属校验只认 `CreatedByUserId`（账号维度），不能认 `AuthorId`**：
> 多个账号可关联同一 Author，用 `AuthorId` 判断会导致互相越权。
> 详情页返回的 `createdByUserId` 就是为此提供的。
