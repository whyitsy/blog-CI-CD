> **用途**：记录项目演进中**已拍板的决策**及其理由，供日后复盘"为什么这么定"。

> **最后核对**：2026-09-11 ｜ **代码依据**：仓库 HEAD
>
> ⚠️ **本文件是唯一的"历史性"文档**——它记录决策过程，而其他文档只描述当前事实。
> 这正是它存在的理由：**代码记录"结果"，文档记录"现状"，只有决策记录回答"为什么"**。

> 想改某个设计？**先在这里找到对应条目，确认当初的约束是否仍然成立。**

### 2.2 T4 的实现含义（容易误解，单独说明）

T4 决定"应用层判断、不新增字段"，因此：

> **判定"作者是否填了摘要"的唯一依据，就是请求里的 `summary` 是否为空。**

这带来两个实现约束：

1. `PostService` 必须**先判断** `request.Summary`，为空时才走自动截取
2. `Post.Update(...)` 的签名**必须接收 `summary`**（不能只在构造时处理）

因为这个约定**容易被误解成"实体自己判断"**，所以在实体里也写了注释：

```csharp
/// <summary>
/// 摘要。为空时自动取正文前 50 字；作者填写后不再被自动覆盖（见 docs/10-决策记录.md T4）
/// </summary>
public string Summary { get; private set; } = string.Empty;
```

### 2.4 T18 细节：为什么日志中间件必须在外层

**问题**：`BusinessException` 会先冒泡穿过日志中间件，
日志记录的是"异常发生时的 500 + 完整堆栈"，
而客户端实际收到的是映射后的 404/403/409。

**后果**：

- **日志与事实不符**（排查时被严重误导）
- "文章不存在""邮箱重复"这类**可预期的业务失败刷满 ERR**，淹没真故障

**修复**：把 `UseSerilogRequestLogging()` 注册在 `ExceptionHandlingMiddleware` **之前**，
并按状态码分级（5xx = ERR / 4xx = WRN / 其余 = INF）。

### 2.5 T18 细节：文件 404 的缓存头

**问题**：用 `[ResponseCache]` 特性标注文件下载 action，
会把"文件不存在"的 **404 也盖上 `public, max-age=86400`**，
于是浏览器把 404 缓存**一整天**——文件补回来后用户仍看到空白，必须手动强刷。

**修复**：改为在方法体内、**确认命中后才设置响应头**。

**教训**：**声明式特性作用于整个方法**，无法表达"只在某分支生效"。
缓存语义有分支时，必须用命令式代码。

## 4. 明确"不做"的事项

这些是**有意排除**的范围，不是遗漏。记录在此以免被反复提起。

| 事项 | 决定 | 理由 |
|---|---|---|
| **SEO**（站点地图、结构化数据、预渲染） | 不做（T10） | 纯 SPA 个人博客，不做搜索引擎优化 |
| **自建评论系统** | 不做 | 外挂 giscus（GitHub Discussions），本站**不存评论数据** |
| **Refresh Token** | 不做（T7） | 只发 Access Token（30 分钟） |
| **作者自助注册** | 不做（T1） | 作者账号由管理员创建 |
| **细粒度 RBAC** | 不做 | 只有 `Admin` / `Author` 两档角色 |
| **内容审核流** | 不做（Q6） | 多作者规模引入时再评估 |
| **国际化（i18n）** | 不做（Q10） | 单语言站点 |
| **UI 组件库**（含 Naive UI） | 不做（E1 / Q13） | 自研 CSS 体系与 Aurora 视觉深度绑定，整体引入冲突成本高于收益 |
| **AutoMapper** | 不做 | DTO 手写映射，显式且编译期可检查 |
| **EF 延迟加载** | 不做 | 易产生 N+1 问题，改为显式 `Include` / 投影 |
| **缓存命中率统计** | 不做（E7） | 收益低，增加运行时开销 |
| **OSS / CDN 对象存储** | 本期不做（Q9） | 保留扩展点，将来迁移 |

> **一个项目的边界不只由"做了什么"定义，也由"明确不做什么"定义。**

## 5. 已废弃 / 被推翻的方案

| 方案 | 为什么废弃 | 被什么取代 |
|---|---|---|
| 乐观锁用 `byte[] RowVersion` + `[Timestamp]` | 依赖 SQL Server 的 `rowversion` 语义，跨库不通用 | `int Version` + SQL 条件手动控制（[03](./03-后端设计.md) §4.3） |
| 双登录入口（`/login` + `/admin/login`、两个登录端点） | `Author` 是署名实体无法登录，双页面只造成命名歧义且**不提供任何安全性** | 合并为单一入口（T16） |
| 静态文件中间件暴露 `/media/**` | 无法做路径穿越防护，缓存头无法按分支控制 | 独立文件接口 `/api/files/**`（Q4） |
| 用 `pg_trgm` 模糊匹配做搜索 | 无法满足中文检索需求 | 真 FTS + zhparser（T9） |
| 前端 `/admin/profile` 独立页 | 与「作者管理」职责重叠（都是维护 `Author`） | 重定向到 `/admin/authors`（T14b） |
| 静默重定向首页代替 404 | 产生**软 404**，搜索引擎与用户都无法判断 URL 不存在 | 真实的 `NotFoundView` |
| `PagedResult.totalCount` 字段名 | 后端实际下发 `total`，前端写 `totalCount` 导致"共 N 篇"渲染为 `undefined` | 统一为 `total` |
| `[ResponseCache]` 标注文件下载 action | 会连"文件不存在"的 404 一起缓存一整天（T18） | 命中后才在方法体内设置响应头 |
| 用 `nohup ... &` 启动后端 | 进程随 Bash 会话被清理，表现为前端突然全部 `ECONNREFUSED` | 用工具的后台任务机制持有进程 |
