# 03-后端任务拆分与开发顺序

> 文档版本：v1.0 | 开发模型：增量交付，每个里程碑结束均可构建通过并用 git 提交

## 里程碑总览

```
M0 文档与基线 ─► M1 Domain 实体完善 ─► M2 迁移与种子 ─► M3 Application 服务层
      ─► M4 WebApi 控制器 ─► M5 Serilog ─► M6 Redis 缓存 ─► M7 令牌桶限流 ─► M8 联调验收
```

---

## M8 联调验收
1. 完整冒烟：首页列表→详情（浏览量+1）→搜索→归档→标签/分类过滤→统计
2. 并发更新同一文章验证 409（乐观锁生效）
3. `git log` 清晰、每个里程碑一至多个 commit

## Git 提交规范
- 格式：`<type>(<scope>): <subject>`，type ∈ feat/fix/docs/refactor/chore/test
- 示例：`feat(domain): add RowVersion optimistic concurrency to BaseEntity`
- 每个里程碑至少一个 commit；docs 目录单独提交
