## 1. 项目概述

个人博客网站，前后端分离架构：

| 端 | 技术栈 |
|---|---|
| 前端 | Vue3 + TypeScript + Vite + Vue Router + Pinia + Naive UI + SCSS |
| 后端 | C# / .NET 10 + ASP.NET Core + EF Core 10（**不使用 AutoMapper**）+ PostgreSQL |
| 架构 | 整洁架构（Clean Architecture）：Domain / Application / Infrastructure / WebApi |
| 中间件 | Serilog（日志）、Redis（缓存 + 限流，均可开关） |

## 3. 页面需求分析 → 功能拆解

### 3.1 首屏（Hero）
- 顶部固定导航栏：背景透明、Logo + 菜单（首页/标签/分类/归档）+ 搜索按钮
- 全屏背景图（`/src/assets/hero-bg.jpg`，缺省用纯色渐变）
- 主文本：大字号，CSS `animation: translateY ±6px` 轻微上下浮动
- 副文本：小字号，打字机效果循环（自封装 Vue 指令 `v-typewriter`）
- 向下按钮：大幅浮动 + 透明度呼吸动画，点击平滑滚动至文章列表锚点
- 社交图标行：来自 `SocialLink` 表，可排序、可隐藏
- 所有动画需适配 `prefers-reduced-motion: reduce`（媒体查询下禁用/简化动画）

### 3.2 文章列表（首页第二屏）
- 卡片字段：封面（空则占位图）、标题、分类、标签、发布日期、内容前 50 字摘要
- 布局：桌面 ≥1200px 三列 / 平板 768–1199px 两列 / 手机 <768px 单列；每页 12 张 + 分页器
- 加载中显示骨架屏（Naive UI `NSkeleton`）
- 两侧预留功能位（广告/公告/个人介绍卡片占位）
- 点击卡片 → 文章详情页

### 3.3 详情页
- 展示全文、分类、标签、发布时间、浏览量；进入页面触发浏览量 +1

### 3.4 标签页 / 分类页
- 按钮墙形式展示全部标签/分类 + 文章数量徽标
- 点击 → 结果页（复用文章卡片列表组件 + 分页器）

### 3.5 归档页
- 时间轴自上而下按发布时间倒序列出文章（年/月分组）

### 3.6 搜索
- 导航栏搜索按钮 → 弹窗 → 输入关键词（防抖 300ms）→ 模糊匹配标题/内容/标签/分类 → 结果列表

### 3.7 Footer
- 建站天数（基于 SiteConfig 建站日期实时计算）、全部文章总字数、总浏览次数、文章数等统计

### 3.8 文件/图片服务
- 图片等文件请求走**独立接口**（不与 API 混用路由），文件存于后端 `wwwroot/uploads/`
- 详情页图片、文章封面统一引用该接口

## 4. 后端横切需求方案

### 4.1 日志（Serilog）
- 包：`Serilog.AspNetCore` + `Serilog.Sinks.File`（控制台 Sink 内置于核心包）
- 输出：控制台 + 滚动文件 `logs/blog-.log`（按天滚动，保留 30 天）
- 记录内容：
  - 请求开始/结束（方法、路径、状态码、耗时）—— `UseSerilogRequestLogging()`
  - 异常堆栈 —— 全局异常中间件 `Log.Error(ex, ...)`
  - 慢查询（>500ms）—— EF Core `DbCommandInterceptor` 记录 SQL 与耗时
  - 缓存命中率 —— `CacheService` 内部计数日志（周期性输出）
  - 限流触发 —— 限流中间件命中拒绝时 `Log.Warning`

### 4.2 Redis 缓存（可开关 + 降级 + 三防）
- 包：`StackExchange.Redis`（不引入 IDistributedCache 封装，自建 `ICacheService` 抽象更可控）
- 配置开关：`Cache:Enabled`（false 时完全直查 DB，代码零侵入切换）
- 降级策略：`Cache:Enabled=true` 但 Redis 连接失败/超时 → 捕获 `RedisConnectionException/RedisTimeoutException`，标记 Redis 不可用（冷却期内不再重试连接，避免每个请求都等超时），自动回源 DB，服务不中断
- **缓存穿透**（查不存在的数据打穿 DB）：
  - 查询结果为空 → 缓存空标记（`null sentinel`），TTL 60s（短）
  - 列表查询用"空数组哨兵"防止恶意不存在 categoryId/tagId 扫库
- **缓存击穿**（热点 key 过期瞬间并发打 DB）：
  - 基于 Redis `SET key value NX PX ttl` 的互斥锁重建：拿到锁的请求回源重建缓存，其余请求短暂自旋（上限 200ms）后读缓存，超时则直接回源（保可用性）
- **缓存雪崩**（大量 key 同时过期）：
  - TTL = 基础值 + `Random(0, 300s)` 随机抖动，打散过期时间
  - 缓存失败不影响业务（所有缓存路径都有 DB 回源兜底）
- 缓存 key 规范：`blog:{module}:{query-hash}`，如 `blog:posts:list:p1s12c:{categoryId}`、`blog:posts:detail:{id}`
- 失效策略：文章/分类/标签写操作 → 删除相关缓存（Cache-Aside，删除而非更新）

### 4.3 令牌桶限流（Redis + 配置化粒度）
- 自定义中间件 `TokenBucketRateLimitMiddleware`，Redis Lua 脚本原子实现令牌桶（取令牌/补充令牌一步完成，避免竞态）
- Lua 语义：桶容量 `capacity`、恒定速率 `tokensPerSecond` 每次请求按流逝时间补充；`INCRBY` 计数拒绝次数用于观测
- 限流粒度配置（appsettings `RateLimit` 节）：

```json
"RateLimit": {
  "Enabled": true,
  "Redis": { "Enabled": true },
  "Global": { "Capacity": 200, "TokensPerSecond": 50 },
  "EndpointRules": [
    { "Endpoint": "/api/posts", "Scope": "Ip", "Capacity": 20, "TokensPerSecond": 5 },
    { "Endpoint": "/api/search", "Scope": "Ip", "Capacity": 5, "TokensPerSecond": 1 }
  ]
}
```
  - `Scope`：`Ip`（按客户端 IP）/ `Global`（全站共享桶）
  - 匹配规则：精确前缀匹配，取第一条命中；未命中端点规则则套用 Global 桶
- 降级：`RateLimit.Redis.Enabled=false` 或 Redis 不可用时 → 进程内 `MemoryTokenBucket`（ConcurrentDictionary + 锁内补币），单机语义不变
- 触发限流返回 `429` + 统一响应体（`ApiResponse` code=4091），响应头带 `Retry-After`
- 客户端 IP 识别：优先 `X-Forwarded-For` 首段（支持反代），否则 `RemoteIpAddress`

### 4.4 乐观锁并发控制
- `BaseEntity` 增加：
  ```csharp
  [Timestamp]
  public byte[] RowVersion { get; set; } = [];
  ```
- EF Core 自动在 `UPDATE ... WHERE RowVersion = @old` 检查，Npgsql 映射为 `bytea`（or `xmin` 可选，此处用显式列以跨库可移植）
- 并发冲突 → `DbUpdateConcurrencyException` → 全局异常中间件捕获 → HTTP 409 + `code=4090`，提示"数据已被他人修改，请刷新后重试"
- **特例——浏览量自增**：`Post.ViewCount` 为高频并发写，若走实体追踪 + 乐观锁会频繁 409。方案：详情页浏览量+1 使用 `ExecuteUpdateAsync(s => s.SetProperty(p => p.ViewCount, p => p.ViewCount + 1))` 数据库原子自增（绕过变更追踪，天然无并发冲突）；其余字段更新走乐观锁。此为有意取舍，已记录于备注
- 写操作 DTO 需携带 `rowVersion`（Base64），服务层赋值到 `entry.OriginalValues` 参与并发检查

## 5. 后端分层与目录规划

```
Blog.Domain          # 实体、仓储接口、领域常量（零框架依赖）
Blog.Application     # DTO、Service、ICacheService、IFileStorage、限流抽象
Blog.Infrastructure  # DbContext、仓储实现、Redis/内存缓存实现、文件存储实现
Blog.WebApi          # 控制器、中间件、DI 装配、Program
```

依赖方向：WebApi → Application/Infrastructure → Application → Domain（保持现有单向依赖）。

- DTO 手写映射（不使用 AutoMapper，符合约束）
- Service 返回 `Result` 型 DTO 或直接抛业务异常（`BusinessException`），由中间件统一转响应

## 6. 统一响应格式（依据补充说明 §4）

```json
{ "code": 0, "data": { }, "message": "ok" }
```
- 成功：`code=0`
- 业务错误：`code=4xxx`（如 4001 参数错误、4040 资源不存在、4090 并发冲突、4091 限流）
- 系统异常：`code=5000`
- HTTP 状态码同步语义（200 / 400 / 404 / 409 / 429 / 500）

## 7. 风险与备注

1. **无认证模块**：本期管理类接口（写操作）不做用户体系，作为已知限制记录；后续可加 JWT（文档已预留扩展点）
2. **Redis 非必装**：本机无 Redis 也可完整运行（缓存/限流自动降级内存实现或直查）
3. **迁移基线**：数据库尚无迁移，首个迁移将包含全部表结构 + 索引
4. **软删除 + 唯一索引**：Name 唯一索引需配合 `WHERE "IsDeleted" = false` 过滤索引，避免软删后无法重建同名数据
5. 文件上传限制白名单（jpg/png/webp/gif/svg），大小上限 10MB，防任意文件上传
